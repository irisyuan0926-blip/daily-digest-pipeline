# 首次搭建清单

## 一、向用户确认的 6 件事（一次性问完，别边做边猜）

| # | 问题 | 缺省值 |
|---|---|---|
| 1 | 日报主题与收录标准是什么？ | 必须问，无默认 |
| 2 | 优先信源有哪些？（先跑连通性测试再定） | 必须问，无默认 |
| 3 | 每天几点推送？ | 19:00 |
| 4 | 通知通道与地址（邮箱 / 飞书 user_id / 企微 webhook） | 至少选一个，否则只在会话内呈现 |
| 5 | 是否发布为在线链接？ | 推荐发布（网址固定、每天覆盖）；不发布就只在本地看 |
| 6 | 署名 / 期号起点 | 期号从 001 起 |

用户没答的：给合理默认 + 在日报里注明「这是假设，可改」。不要停下来等。

## 二、通道选择与降级

优先级：**网页（内容承载）> 会话内呈现（保底）> 邮件（留档）> IM（即时提醒）**

| 通道 | 作用 | 不可用时的降级 |
|---|---|---|
| 网页版 | 承载全部内容，可筛选、可点、可存档 | 无发布能力 → 生成本地 HTML，在会话里用文件卡片呈现 |
| 会话内 | 每次运行必定可见 | —— |
| 邮件 | 每日留档、手机上留存 | 未开通 / 报错 → 跳过并在回复里提醒，不重试不阻塞其他通道 |
| 飞书 / 企业微信 | 即时提醒，通勤路上能看 | 命令不存在 → 降级为会话内呈现 |

**铁律：任何单通道失败，不阻塞其他通道，也不阻塞网页发布。**

## 三、固定产物路径（建议照抄，省得每次想）

```
<你的日报目录>/
  YYYY-MM-DD.md              日报原文（markdown 归档）
  .feishu-today.md           推送用的精简版（一屏半以内）
  web/index.html             网页版，发布目录，每天覆盖
  templates/
    digest_data_YYYY-MM-DD.json   结构化数据
    render_web.py                 网页渲染器
    render_email_digest.py        邮件摘要渲染器
```

## 四、落地成定时任务的要点

把下面这些**写进自动化 prompt**，否则每天重跑会走偏：
1. 用户画像与收录标准（决定「什么算值得收录」）
2. **网络可达性结论**（已测过的可达/不可达域名清单，避免每天重复踩墙）
3. 信源清单（分国内/海外，注明哪些要人工判断）
4. 过滤规则（只收未来仍可参与的、必须有链接、不许编造、与上一期去重）
5. 渲染 / 发布 / 推送的**具体命令与参数**（含路径、体积门槛、发布后校验命令）
6. 交付要求（回复里说清新增了什么、哪几条紧急、各渠道命中与阻断情况）

## 五、换主题 / 改配色

- 只想换头图：`render_web.py out.html fresh`（默认，只动 banner，正文不动）
- 整页换色：`mint`（薄荷青）/ `sky`（晴空白蓝）/ `warm`（暖阳米白）
- 自定义：改 `THEMES` 里对应的 `:root` 变量块即可，骨架不用碰
- **改完必测**：确认 style 里 BASE 在 THEMES 之前（顺序反了主题不生效，见 pitfalls）

## 六、验收自查（每次跑完过一遍）

- [ ] 每条都有真实链接，且链接来自检索结果（非编造）
- [ ] 与上一期去重过
- [ ] 抓不到的信源在「缺口」里如实标注了
- [ ] 网页发布后 `curl` 返回 200 且条目数对得上
- [ ] 邮件 / IM 末尾附了网页明文地址（按钮可能失效）
- [ ] 邮件只有一封，体积 < 10KB
- [ ] 回复里说明了：新增了哪些、哪些紧急、各渠道命中与阻断
